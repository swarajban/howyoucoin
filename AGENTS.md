# How You Coin — agent handoff

## Product and priorities

This is an infinite marble runner, primarily for iPad/iPhone touch browsers. Graphics, responsive steering, and game feel are the highest priorities. The user prefers autonomous implementation and testing, with a link when changes are ready to try. Keep the name **How You Coin**; `neon-drift` is only the legacy source directory/package name.

Production: https://howyoucoin.vercel.app
Repository: https://github.com/swarajban/howyoucoin
Vercel project: `howyoucoin`. Deployment configuration lives at the repository root. Vercel is the active host; any local `.openai` hosting metadata is obsolete and intentionally ignored.

## Setup and source map

Follow README.md for install, build, preview, browser tests, and deployment commands. Run npm commands inside `neon-drift`, and Vercel deployment commands at the repository root. No application secrets or backend are required. Install Node.js/npm and Python 3 for the documented local workflow.

- `neon-drift/src/core.js`: deterministic course generation, movement, collision helpers, speed, and coin charge.
- `src/main.js`: game loop/state, input, UI, settings, hints, and persistence.
- `src/scene.js`: Three.js renderer, road, rolling marble, reflections, and scene composition.
- `src/themes.js`, `src/landscape.js`, `src/exotic-worlds.js`: five selectable worlds.
- `src/obstacles.js`, `src/power.js`, `src/audio.js`: detailed obstacles, star effects, and synthesized sound.
- `neon-drift/dist/index.html` and `dist/style.css` are editable source assets. Do not delete `dist` as a disposable build directory. `dist/game.js` is generated by `npm run build` and committed alongside source. Fonts, licenses, icons, and manifest are also tracked there.
- `neon-drift/test`: unit checks and Playwright scripts. Browser tests expect a local preview at port 4173. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if using a preinstalled Chromium.

## Current gameplay decisions

- Coins fill a visible meter: every 100 coins automatically activates six seconds of star power. Coins during star power count toward the next activation. Distance is the personal-best score. Star power breaks blocks/barriers and supports the marble at road height across gaps and beyond both road edges. Steering and jumping remain unrestricted; normal falls resume immediately on expiry if the marble is not over solid road. No floating star pickups remain.
- Hints default to the first three runs per browser/device. Explicit on/off overrides persist. Switching hints off must immediately hide all transient hints, including resume/boost/sector/star messages; the essential HUD stays visible.
- Steering is critically damped, with no spring overshoot. Deliberate movement beyond either road edge must remain possible, with falls prevented only while star power is active.
- Latest tuning: after the opening tutorial stretch, every tenth 40 m course chunk is a boost and other chunks contain hazards. Previously some chunks were empty and boosts were every seventh chunk. Keep enough spacing for consecutive jumps; shrinking chunks also changes coin pacing.
- Speed ramps from 18 m/s toward 38 m/s, plus temporary boosts. Five themes: Night Shift, Golden Dunes, Cloud Forest, Prism Orbit, and Abyssal Bloom.
- Scenery must approach in the same direction as the road; rolling marble reflections should respond to moving scenery.

## Verification and continuation

Build and run `npm test` after gameplay changes. Run the relevant Playwright scripts with the preview server running. `gameplay-check.mjs` drives a deterministic 2.5 km run through all hazards, checks death/retry/persistence, and suppresses draw calls for speed. Rendered checks complement it; simulated gameplay is not a GPU performance benchmark. `coin-meter-check.mjs` checks coin thresholds, repeated activations, pause/reset, and hint behavior. The read-only `window.__howYouCoin` diagnostics (also aliased as `__neonDrift`) support browser tests.

The latest obstacle-frequency change passed build, unit tests, and the 2.5 km gameplay check and was deployed to production. Actual iOS Safari hardware performance still needs hands-on verification; Chromium touch emulation is not a substitute.

Keep lockfiles and font licenses. Never commit `.env*`, `.vercel`, `.openai`, `node_modules`, credentials, or temporary screenshots. A fresh checkout may need authenticated `vercel link --project howyoucoin` before deployment; local linkage is deliberately ignored. No reference photos or files from `/tmp` are required to run the game.
